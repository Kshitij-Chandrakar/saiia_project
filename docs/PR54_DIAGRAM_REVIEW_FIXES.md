## Disposition of remaining findings

- E, schema: no blanket removal of Pydantic string/array constraints. Current official OpenAI Structured Outputs documentation identifies additional keyword restrictions for fine-tuned models; this service accepts base `gpt-4.1-mini` and dated base snapshots, not fine-tuned IDs. The proposed review did not establish that all emitted constraints must be removed for this model. Mock request-contract tests assert strict output, no tools, `store=false`, required additional-properties restriction and preservation of the actual Graph schema's length/pattern/array bounds. Full local validation remains mandatory. No shared schema is mutated, and no live schema acceptance is claimed. Reference: https://developers.openai.com/api/docs/guides/structured-outputs .
- F, cancellation: confirmed. Awaiting shielded producer cancellation previously raised CancelledError in an uncancelled HTTP waiter. `asyncio.wait` now separates producer completion from waiter cancellation without relying on Python 3.11-only Task.cancelling(). The waiter's own cancellation, including simultaneous producer cancellation, propagates. Producer cancellation finishes/awaits bounded durable cleanup even if shutdown cancels it again; tasks and exceptions are consumed. Four gated tests cover producer, waiter, simultaneous and shutdown; no extra provider/checkpoint occurs.
- G, SQL registration: confirmed. `npm --prefix backend/tests test` now includes diagram/source SQL after the existing three scripts. PGlite remains pinned at 0.5.8 in the unchanged lockfile. All four scripts executed successfully against isolated storage. This is not hosted or multi-connection PostgreSQL evidence.
- I, pending slots: confirmed. An operation-owned finally cleanup releases slots on non-OK, stale, projection and thrown failures. Object ownership prevents an older failure from deleting a newer same-key entry, even with the same operation ID. Processing/checkpoint tracking remains for real pending backend work; releasing a local slot does not cancel uncertain work or authorize regeneration. Tests exceed sixteen distinct failed sources, exercise throws, same-key races and cancelAll.
- J, canonical history: blanket 8000/48000 increase rejected. Existing transcript SQL char_length admission and Python cloud normalization are 4000 question / 24000 answer Unicode code points. Bridge projection now preserves complete admitted text and rejects unsupported rows instead of slicing JavaScript UTF-16 units. Renderer hashing uses the same code-point bounds. Boundary tests cover maximum ASCII question and maximum non-BMP answer, full-text hash acceptance, and one-over-limit rejection. Canonical text is not silently truncated or rehashed after truncation.
