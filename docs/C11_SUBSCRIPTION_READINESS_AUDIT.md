## 1. Verdict and evidence boundary

Intervucopilot has a substantial live-answer assistant and authenticated resume/session workspace. It is not yet an authoritative subscription product. No implemented plan catalog, commercial subscriptions, payment processing, entitlement service, or durable billable-usage ledger was found in the inspected runtime, migrations, or frontend. Local backend operation and alternate unauthenticated paths must be addressed before selling access to company-funded providers.

The reference image describes a broader interview-preparation product than the code demonstrates. Launch candidates are resume extraction/review and grounding, job-context personalization, live/manual answer assistance, transcription, screen analysis, session history/text exports, transcript-based AI Notes, and session-scoped Ask AI. Each still requires its own release and commercial-control checks. Mock-interview orchestration, scored assessment, learning plans, and performance analytics cannot be advertised as existing products on this evidence.

Baseline: branch `dev/current-work`, HEAD `bff9827`; findings refer to the current mixed working tree, including uncommitted files, not HEAD alone. ## 5. Enforcement and trust-boundary audit

### Confirmed code facts

Electron defaults to `http://localhost:8000` (`frontend/electron/main.cjs:498`). Provider credentials are read by backend settings (`backend/app/config.py:40`, `:126`, `:138`, `:189`); values were not inspected. gRPC deliberately rejects non-loopback binding and uses an insecure local listener (`backend/app/grpc_server.py:858`, `:868`). These facts support a local development/capture architecture, not a trusted paid-access boundary. Documentation says Electron does not provision Python (`docs/G12_GRPC_AUDIO_CLOSEOUT.md`, remaining limitations).

The HTTP application mounts legacy and cloud routers together with no global auth dependency (`backend/app/main.py:56`, `:64`). Cloud resume/job/session routes derive identity from CurrentUserDep. However generation auth is conditional on supplied cloud IDs: clearing all cloud IDs returns without auth (`backend/app/api/generate.py:261`, `:269`). Plain transcription (`backend/app/api/transcribe.py:46`), legacy extraction/index (`backend/app/api/resume.py:80`, `:122`), old JD extraction (`backend/app/api/job_context.py:71`), STT WebSockets (`backend/app/api/auto_stt.py:174`, `:249`), and older screen endpoints (`backend/app/api/screen_ocr.py:281`, `:365`) have no equivalent commercial admission. New screen context permits loopback local mode without auth and validates cloud ownership only when cloudSessionId is supplied (`backend/app/api/screen_context.py:191`, `:200`). gRPC cloud authorization is opt-in and separate from local sessions (`backend/app/grpc_server.py:701`, `:717`; `backend/app/grpc_cloud_context.py:37`). No subscription checks were found on these routes.

These are existing local compatibility paths, not a claim that they are internet-exposed today. Publishing this application unchanged with company provider credentials would create bypass opportunities. CORS, renderer restrictions, feature flags, local counters and immutable session model bindings cannot authorize paid access against a user who controls local code/processes.

### Required commercial boundary (recommendation)

Company-paid inference, authoritative identity/entitlements/quota reservations, billing/webhook writes and reconciliation must execute on a trusted hosted service. Keep capture, UI and optional local/BYOK work on the device; local BYOK availability after expiry is a separate product decision. A local capture broker may send bounded authenticated audio/image requests to hosted compute; it must never hold company service-role/payment/provider secrets. A local proxy is not sufficient if it can call providers itself with company keys.

Hosted STT/audio is an architectural prerequisite: today's system loopback capture executes beside the backend on Windows. Moving that backend to a server would capture server audio, not the user's audio. Define a device capture-to-host protocol and preserve cancellation, sequence/timestamp, combined-mix and privacy semantics. The current loopback-only insecure gRPC server must not simply be rebound publicly. Public TLS/auth, per-user admission and streamed lease enforcement require deliberate transport design.

Inventory every expensive path before enabling hosted inference: all generate variants (stream/buffered/managed/retry/recovery), STT upload and both WebSockets, gRPC manual/Auto/local/cloud, direct screen answers/context/retry/legacy OCR, resume extract/re-extract/index rebuild and JD extraction, Notes/regeneration, Ask AI/retry, diagram generate/retry, and any debug/refinement/legacy helper reaching providers. Reuse final-answer and Ask AI claims for identity/replay coordination, not as an already-correct quota ledger. Supabase service-role clients bypass RLS, so each backend method/RPC must independently bind verified owner identity; clients must never write billing or usage authority.
