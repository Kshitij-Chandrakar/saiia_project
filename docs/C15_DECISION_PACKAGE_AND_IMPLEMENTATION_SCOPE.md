## 4. Implementation-ready lifecycle contracts

These are design requirements for later implementation, not schemas, migrations or runnable API definitions.

- **Self-service request:** server derives subject from verified identity; a preview identifies scope/retained exceptions. Reauthentication creates a short-lived target/action/policy-version-bound confirmation receipt. Confirmation atomically consumes it with request, restriction, audit and outbox. Same request replay returns the same status; conflicting scope/key fails safely. No admin permission or staff-approved deletion record on this path.
- **States:** unconfirmed draft/cancelled-before-confirmation; accepted-and-restricted; cleaning; primary-content-removed; retention-or-billing-pending; complete-for-declared-scope. Failures retain the restriction and task checkpoints. Show per-category exception/cleanup errors. Status must distinguish account identity unlink from private payload removal. Never report full success merely because work was queued or Auth is gone.
- **Late-write safety:** consistent account/resource lock order and revision/fence checks at acceptance and commit; stop active work, revoke handoffs/sessions as supported, reject late uploads/activation/generation/notes/chat writes. Retained replay/deletion suppression prevents callbacks/restores from rebootstrap. No deletion-driven plan reset, entitlement grant or restored initial-upload eligibility.
- **Jobs:** bounded per-resource manifest/outbox, leases/fences/idempotent absence verification, retries only unfinished tasks and durable unknown-outcome recovery. Object calls are not in the DB transaction. A failed object delete cannot discard its task or restore access. Content/credentials stay out of task/audit payloads.
- **Export:** allowlisted fields and owned references, deterministic snapshot cutoff, bounded archive paths/size, recent auth/download authorization, private expired artifacts inaccessible. Deletion wins over unfinished/ready export publication; cleanup includes archives and partial artifacts. No raw database dumps or arbitrary object traversal.
- **Resource scopes:** preserve transcript-only behavior. Resume erasure must cover row extraction/chunk generations/object and explicitly identify separate copied profile/snapshot treatment. Session/history erasure follows C6 only after approval. Each control states retained derivatives; absence of a row or UI item is not verified physical cleanup.
- **Billing:** candidate content need not remain for mandate management. Preserve only approved minimal linkage and restrict contact use; no ordinary welcome/marketing or personal content from late events. Provider cancellation requested/unknown/scheduled/effective/failed stay distinct. Never claim receipt equals tax invoice or request equals cancellation.
- **Status/notifications:** narrow subject-owned status proof must survive ordinary login restriction without restoring general access; opaque, scoped, expiring proof is not a full access token. Notify request acceptance versus actual personal-content completion separately using reviewed safe email event types. Uncertain delivery does not roll back cleanup or trigger blind duplicate sends. Sensitive lifecycle audit includes safe identity/login/password/export/delete/subscription events without content.
- **Restore/local cleanup:** restriction/tombstone journal survives restoration, is pseudonymous rather than anonymous, and outlives approved restore/callback windows. Restore stays isolated until replay. Device cleanup is limited to controlled account-owned data; disconnected/unmanaged devices and downloaded/shared copies are disclosed exclusions, with no guaranteed remote wipe.
