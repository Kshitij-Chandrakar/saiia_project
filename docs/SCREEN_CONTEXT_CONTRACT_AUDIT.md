## Outcome invariant

`backend/app/models/screen_context.py:23` defines `OUTCOME_RULES`, shared by provider schema generation, semantic validation, response adaptation, response validation and schema tests. Independent exhaustive combination tests guard the table's meaning.

| Outcome | Genuine evidence | Complete means answerable | Answer items | Missing details | Clarification/conflicts | Commit |
| --- | --- | --- | --- | --- | --- | --- |
| answered | Required | true | Required | Empty | Empty | Source + answer |
| reference_accepted | Required | false | Empty | Empty | Empty | Reference source only |
| needs_more_content | Required | false | Empty | Required | Empty | Source only |
| needs_clarification | Null | N/A | Empty | Empty | Clarification required; conflicts optional | Never |
| failed | Null | N/A | Empty | Empty | Empty | Never |

Action controls allowed outcomes: reference capture permits reference_accepted/needs_clarification/failed; New and Continue permit answered/needs_more_content/needs_clarification/failed. Context kind describes retained material. Continue over reference context can answer. The current nested strict provider schema already enforced this matrix before this audit; no current schema contradiction was reproduced.

## Confirmed defects and corrections

1. **Provenance loss across commit.** `frontend/electron/screen_context_execution.cjs:168` previously validated the delta then passed only `controllerResult` text/complete to the controller. `createScreenContextController.commit()` (`frontend/electron/screen_context_controller.cjs:184`) reconstructed a single current-image source, discarding supporting-image links. Execution now passes a private validated provenance sidecar. Stored `SourceEvidence` retains `imageHashes`, `replacesTurnIds` and main-owned `kind`. Controller independently checks these against the frozen candidate and selection before atomic commit. Provider output and minimal controller result are unchanged; malformed provenance is rejected.
2. **Replacement attribution loss.** The controller previously accumulated replacement targets globally and repeated them on every later turn. This preserved which old turns were selected but lost which accepted turn replaced them, leaving old source content active without an explicit graph. Each accepted source now records its replacement edges. Current `replacesTurnIds` contains only the current explicit selection; historical relationships survive inside accepted evidence. Backend reference validation (`models/screen_context.py:133`) rejects self/future/unknown replacement edges and unknown/duplicate supporting hashes. `answer_context()` computes explicit active/superseded turn lists and labels superseded sources/images as historical provenance, never authoritative code/constraints. Source records/images remain in the bounded memory log; no history deletion or silent eviction was introduced.
3. **Reference identity inferred from position.** Provider input previously called the first evidence record the reference whenever contextKind was reference. Reference identity now comes from `SourceEvidence.kind == 'reference'`, assigned by main on explicit reference capture. No array-position inference is used. Legacy v1 requests without provenance remain accepted but are not assigned invented reference identities.
4. **Successful clarification disappeared.** Pending clarification was sent during resolution but discarded after successful commit. Accepted clarification is now retained in a separately typed/bounded `input.clarifications` list, linked to its originating thread/turn/request. It is supplied in a separate untrusted user-clarification section, outside observed source evidence and fallible AI answers. Only a successful evidence/answer commit retains it; clarification outcomes themselves still commit nothing. Cancellation/reset/lifecycle cleanup clear pending bindings and accepted working clarifications as appropriate.
5. **Controller completeness invariant.** Private commit validation previously accepted an answered payload with complete=false, or an evidence-only payload with complete=true, if invoked without the executor. The authoritative commit method now enforces the same completeness rule as schema/parser/response validation. Invalid calls leave state unchanged.
6. **Unicode character mismatch.** Python limits count Unicode code points, while Electron used UTF-16 length. A 12,001-emoji evidence field fits the 24,000-character and 64-KiB provider-output limits but exceeded Electron's old character check. Electron validation and controller text checks now count code points. UTF-8 upload/output byte limits and UTF-16 retained-memory estimates remain separate and unchanged. Real multipart/provider JSON/backend serialization/Electron commit tests cover this case.
7. **Blocking preparation and uncontrolled preparation errors.** Image decoding/compression ran synchronously inside async `encode_images()`, blocking the endpoint event loop and delaying cancellation/deadline observation. Unknown `_prepare_image()` errors also escaped the endpoint's controlled error contract. Bounded image work now runs off-loop. The existing two-slot endpoint gate bounds owned workers. Cancellation sets a cooperative stop flag, waits for the current bounded image to finish and release resources, skips subsequent images, and only then releases the endpoint slot/buffers. No worker is abandoned or detached. Known invalid image/resource errors retain their safe codes; unexpected preparation errors become controlled `image_preparation_failed` responses. A blocked-worker test proves event-loop responsiveness, cancellation ownership, no second decode and slot retention until cleanup.
8. **Failure classification loss.** Provider timeout, rate limiting, configuration/auth/model errors and transport connection errors were collapsed into generic provider_error. They now produce safe allowlisted codes and actionable UI text, while preserving captured retry input. Missing API key is configuration failure without a provider call. Endpoint HTTP 504/429 map to timeout/busy status in Electron. Exceptions/messages/bodies are never exposed. Unknown errors remain generic.

## Suspected issues disproved / already covered

- **Stable question identity:** executor `snapshot.priorItems.find(...)` (`frontend/electron/screen_context_execution.cjs:170`) reuses the original question binding. A targeted answer in turn B does not rewrite the originating A:index identity. Original question → targeted answer → second target and multi-question target 2 now pass actual serialization/validation/commit tests. No stable-ID schema redesign was necessary.
- **Revision coupling:** the controller is deliberately append-only. Every accepted answered/reference/incomplete result appends exactly one evidence record and increments revision exactly once (`screen_context_controller.cjs:222`). Replacement changes authority via explicit edges; it does not remove log entries. Therefore baseRevision == evidence count is valid for this storage model. Failures/clarifications/cancellations do not increment it. The invariant is documented and tested rather than generalized speculatively.
- **Clarification linkage:** `createScreenContextExecution.resolve()` checks the exact pending clarification request ID before controller access; `controller.resolveClarification()` (`screen_context_controller.cjs:270`) checks the exact retained attempt ID again, plus known targets/replacement sources. The stateless backend's differing-attempt check is not the sole linkage guard. New tests exercise incorrect IDs before successful resolution and subsequent retained clarification.
- **Preparation outside the provider try:** this placement alone was not a defect. `api.analyze_context()` already catches controlled `ScreenContextError`, and its 45-second deadline covers parsing/auth/preparation/provider/response work. The confirmed gaps were event-loop blocking and unknown preparation exceptions, fixed above. The inner provider deadline remains capped at 30 seconds. Cancellation cleanup can extend beyond the deadline for the current bounded decode; it cannot commit a late result or start another model call.
- **Partial reference readability:** existing extracted evidence and missing/clarification fields plus retained images can represent readable portions and uncertainty. No confidence field or new reference UI behavior was introduced without a demonstrated requirement.
- **Isolation/lifecycle/history:** passive chooser behavior, reset only on explicit OCR execution, fresh reference replacement/New context, frozen retry, stale response fencing, memory limits, session/account cleanup and saved answer history remain covered by the existing Node/Playwright suite. No Ask AI/transcript/resume/job-content retrieval was added.
