## Restricted preparation and read-only eligibility

New tables: `privacy_retirement_configuration`, `privacy_retirement_units`, `privacy_retirement_members`, `privacy_retirement_holds`, append-only `privacy_retirement_preparation_events`, and the private sidecar. All new fields have explicit schema-drift treatment. No role receives retirement DELETE/UPDATE/TRUNCATE on legacy history.

`privacy_preparation_executor` is NOLOGIN/no inheritance/no superuser, with only fixed preparation, hold-CAS and bounded report EXECUTEs. No role assignments, app routes, invitations or C15.5 UI are added. Preparation is default **disabled**. Members are fixed definitions for new v2 Auto envelopes and already minimized metadata; caller-supplied table names/predicates/SQL are never accepted. No historical payload backfill occurs.

Accepted clock provenance is an owner-matched accepted deletion request. New usage/recovery units use confirmation +90 days; classified security/audit metadata uses +180 days, with UTC interval verification. No recorded_at/subscription/Auth-absence clock is substituted. Member ownership/class/clock, run revision, live leases, private-payload erasure, reader compatibility, known dependency closure and complete membership are rechecked read-only. Unit/report eligibility is **preparation only**, never account completion or execution permission.

| Condition | Result / blocker |
| --- | --- |
| Disabled configuration | Preparation denied; report reflects disabled units. |
| Financial/shared/unclassified category | `unsupported_category`; no automatic 90/180-day lifetime. |
| Missing/foreign acceptance or modified deadline | Missing clock/ownership denial or `clock_mismatch`; no inferred backfill. |
| Wrong owner, mixed member class, stale run revision | `ownership`, `mixed_class` or `revision_stale`. |
| Active run/operation/retention lease | `active_writer`. The existing deletion preparation already disconnects Auto; tests use a genuine retention lease to exercise remaining active-worker blocking. |
| Private response still present | `private_payload_present`; no pretending an envelope alone proves erasure. |
| Legacy/unknown reply within the same run or missing source | `reader_compatibility` / `source_already_removed`; no generic legacy retirement. |
| Unexpected incoming FK | `dependency_gap`; no constraint/trigger bypass. |
| Source/member set changed or incomplete | `coverage_changed` / `coverage_gap` / `coverage_limit`. |
| Active hold or overdue review | `hold` / `hold_review_due`. Review expiry never authorizes deletion automatically. Hold updates use revision CAS and append-only safe events. No new business review period is invented. |
| Verified prerequisites and approved elapsed clock | `eligible_preparation_only`; execution remains false. |

Engineering bounds are 100 report units and 1,000 members per unit. Collection stops at 1,001 solely to detect overflow; a partial member set never qualifies. These are bounded local implementation limits, not retention policy or silent truncation. Reports return aggregate reason counts, classifier/source scope, a pagination coverage flag, **`complete_account_coverage=false`** and **`execution_enabled=false`**. They expose no email/subject lists, private payload, unit IDs or public identification endpoint. Draft/no-clock units are not silently rebound to later clocks: conflicting preparation identity remains blocked pending explicit metadata review.

## Cleanup, retention and restore

Whole-account cleanup calls `privacy_auto_payload_erase(job_id, lease_id)` through the existing local durable worker connection. The function derives subject from a live account-cleanup job and accepted request, checks the exact lease/expiry, then clears response/checksum and records erased state with its job reference. It cannot edit an immutable envelope or select arbitrary resources. Ordinary roles cannot execute it. Stale leases reject; repeat erasure is idempotent; committed erasure survives worker restart and later cleanup retry.

Minimal erased markers and their referenced request/job evidence remain restricted under the separately justified restore/replay horizon; no automatic 90/180-day marker expiry is assigned. The fixture preserves referenced jobs rather than dropping FK/marker protections to clean a test queue. No retirement guard was relaxed.

The sidecar is classified as private lifecycle/credential material and excluded entirely from own-account exports, including its checksum. Safe usage totals remain available through the existing approved projections. The frozen manifest now includes all new columns/types; unknown schema still blocks coverage. Existing Clear Transcript/five-minute guard, ordinary saved-answer immutability and session-versus-account reusable-resource scope remain unchanged. Auto capability sidecars are account/run recovery state, not a new session-content delete route; ambiguous session associations do not cause guessed cleanup.

A native cold snapshot taken before deletion restores an available sidecar into an isolated clone. Independent account-deletion evidence is replayed first; actual SQL Auto access denies the restored subject, then the existing cleanup worker erases the restored sidecar again. Old replies cannot republish content or regain access. This is native PostgreSQL with synthetic Auth/fake Storage boundaries, **not actual Auth/Storage/processor acceptance**. SQL live-value removal does not promise forensic tuple/backup erasure. Legacy mixed payloads keep overall account cleanup honestly blocked.
